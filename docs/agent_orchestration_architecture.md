## 2. Institutional Architectural Principles

### 2.1 The Cardinal Rule: Zero LLM Financial Arithmetic
The Large Language Model (LLM) is an **orchestration, reasoning, and synthesis layer**; it is **NEVER a calculator**. All financial sums, EBITDA adjustments, DCF valuations, WACC calculations, risk score aggregations, VaR computations, and synergy phasings are executed deterministically by audited domain engines. Specialist agents query deterministic tools and propagate verified numbers into typed assessment models.

### 2.2 Grounded Evidence Provenance
Every factual finding generated by an agent must maintain strict citation lineage back to source documents, page numbers, and exact quotes in the Diligence Data Room. Fabricated claims without verifiable evidence are rejected by `AIGuardrailValidator`.

### 2.3 Strict Tenant Isolation
All agent executions, specialist tool calls, and persistence records are hard-scoped to the authenticated `organization_id` and deal workspace boundary. Cross-tenant access is rejected at the API dependency layer (`validate_deal_membership`).

## 3. Core Architectural Layers

### 3.1 Standardized Agent Contract (`contract.py`)
All agents adhere to a strict, typed contract:
- `AgentId`: Unique identifier (`finance_intelligence_agent`, `valuation_intelligence_agent`, `risk_intelligence_agent`, etc.).
- `AgentMetadata`: Name, purpose, domain, lifecycle phase (`PRE_DEAL_ACQUISITION`, `POST_DEAL_VALUE_CREATION`), and `allowed_tools` whitelist.
- `AgentExecutionRequest`: Scoped by `deal_id`, `organization_id`, `user_id`, and optional focus `query`.
- `BaseAgentAssessment`: Structured machine-readable output with status, confidence level, numeric confidence score, key findings, citations, positive/negative drivers, tools invoked, and execution timing.
- **9 Typed Domain Assessments**:
  - `FinanceAssessment`: Reported revenue, normalized EBITDA, QoE net add-backs, margin expansion.
  - `ValuationAssessment`: DCF implied enterprise value range, WACC rate, valuation multiples.
  - `RiskAssessment`: 17-pillar composite risk score, critical risk count, risk distribution.
  - `LegalAssessment`: Contract value at risk (VaR), change-of-control clauses, consent requirements.
  - `TechnologyAssessment`: Technology risk score, AWS/cloud hosting spend ratio, tech debt findings.
  - `ScenarioAssessment`: Downside scenario probability, Monte Carlo 5th percentile EV.
  - `IntegrationAssessment`: 100-day health score, critical path milestones count, open blockers.
  - `SynergyAssessment`: 5-year net present value (NPV), annual run-rate cost and revenue synergies.
  - `DecisionAssessment`: Overall recommendation (`BUY`, `BUY_WITH_CONDITIONS`, `RENEGOTIATE`, `HOLD`, `AVOID`, `INSUFFICIENT_EVIDENCE`), deterministic score reference, positive/negative drivers, unresolved issues, and human review escalation.

### 3.2 Tool Registry & Whitelist Enforcement (`tools.py`)
`AgentToolRegistry` maintains explicit tool definitions (`ToolDefinition`) with deterministic flags and domain tags. Agents must explicitly whitelist tools in `allowed_tools`. Any attempt by an agent to invoke an unauthorized tool raises `UnauthorizedToolAccessError`.

### 3.3 Agent Orchestrator & Supervisor (`orchestrator.py`)
`AgentOrchestrator` is the supervisor coordinating multi-agent diligence workflows:
- **Taxonomy & Intent Routing**: Routes requests based on mode (`FULL_DEAL_DECISION`, `TECH_AND_INTEGRATION_RISK`, `FINANCIAL_AND_VALUATION`, `LEGAL_AND_RISK`, `CUSTOM`).
- **Parallel Bounded Concurrency**: Executes specialist agents concurrently using `asyncio.gather` with individual 15-second timeouts (`asyncio.wait_for`).
- **Failure Containment**: Specialist agent errors are contained gracefully without crashing the overall pipeline.
- **Decision Synthesis**: Aggregates all specialist outputs into `DealDecisionAgent` for unified institutional synthesis.

### 3.4 Human-In-The-Loop Governance (`human_review.py`)
The system evaluates automatic escalation triggers:
1. `LOW_CONFIDENCE`: Overall confidence score $< 0.70$.
2. `CRITICAL_RISK_DETECTED`: 1 or more critical-severity risks identified.
3. `CHANGE_OF_CONTROL_CONSENT_REQUIRED`: Material customer contracts requiring buyer consent.
4. `UNRESOLVED_DILIGENCE_GAPS`: Incomplete data room evidence or missing audited 3-statement filings.

## 4. Machine Learning Foundation & XAI Architecture

### 4.1 Production Model Contracts (`ml/schemas.py`, `ml/interfaces.py`)
Interfaces established for future institutional ML integration:
- `ModelMetadata`: Framework (e.g. `scikit-learn`, `xgboost`, `lightgbm`), task type, hyperparameters, and validated evaluation metrics (AUC-ROC, RMSE, $R^2$, F1).
- `FeatureSet`: Standardized feature snapshot vectors.
- `PredictionRequest` & `PredictionResult`: Reproducible inference payloads.
- `ModelRegistry`: Registered architecture catalog.

### 4.2 Explainable AI (XAI) Contracts (`ml/schemas.py`)
- `FeatureImportance`: Normalized feature attribution rank and direction.
- `SHAPValue`: Exact TreeSHAP / KernelSHAP values (`base_value`, `shap_value`, `actual_value`).
- `XAIExplanation`: Full explanation metadata with narrative summary. Zero fake or fabricated SHAP values.

### 4.3 Standard Model Architecture Catalog (`ml/registry.py`)
1. `dealguard-revenue-forecast-v1`: Institutional ARR & revenue time-series forecaster.
2. `dealguard-ebitda-qoe-v1`: Normalized EBITDA & QoE realization predictor.
3. `dealguard-customer-churn-v1`: Enterprise customer churn classifier.
4. `dealguard-risk-probability-v1`: 17-pillar downside risk probability model.
5. `dealguard-integration-failure-v1`: 100-day post-merger bottleneck predictor.
6. `dealguard-synergy-realization-v1`: M&A synergy realization estimator.
7. `dealguard-post-acquisition-health-v1`: Continuous enterprise health monitor.
